# Changelog

## Version 1.001 — 2026-08-01

Regenerated by `tools/build_fonts.py`. K24's OTF and TTF both came from the same
FontForge source and differ only in outline flavour, so both are kept as masters;
the web files are generated from the TTF. Outlines are untouched — bounding-box
drift is 0 units.

### Glyph added

- **K24 Bold had no Arabic question mark (U+061F).** It was present in Light but
  missing from Bold in both OTF and TTF, so a Kurdish question could not be set in
  the bold weight. The glyph was constructed by mirroring the font's own Latin
  `question` glyph about its advance width, which is the relationship the two
  forms have anyway, so it stays on-weight and introduces no new drawing. Its left
  sidebearing is set from the mirrored bounds. This is the only glyph-level change
  made to any font in this repository.

### Naming

- Removed the FontForge build string `FontForge 2.0 : K24 Bold : 1-8-2026` from
  the unique ID and replaced it with a proper per-face identifier.
- **Added the designer credit.** Manufacturer, Designer and Description records
  were entirely absent, so the font credited RTLtype nowhere even though the
  documentation did.
- The original copyright notice, `Copyright (c) 2015 by RTLtype. All rights
  reserved.`, is preserved verbatim, with the packaging note appended after it.
- Added the licence description and URL.
- **Fixed style linking.** Light now forms its own family with `Regular` as its
  subfamily, with typographic family/subfamily tying the two weights together.

### Metrics

- Vertical metrics are now identical across both weights; Light and Bold
  previously differed by a unit in `usWinDescent` and `hhea.descender`.
- **U+0695 (ڕ) was clipping.** Its tail reaches −428 in Light and −493 in Bold,
  against a `usWinDescent` of 413/412 — so the descender of a Kurdish letter was
  cut off. Window metrics now cover every glyph.
- Set `USE_TYPO_METRICS` and raised OS/2 to version 4, the first version in which
  that bit is defined.

### Style bits

- Set the `REGULAR` bit on Light, which had no style bits set at all.
- PANOSE weight corrected per weight.

### Cleanup

- **Removed the dead `hebr` script records** from GSUB and GPOS. The font declared
  Hebrew support while containing zero Hebrew glyphs.
- Removed the FontForge `FFTM` timestamp table.
- Rebuilt `cmap` as Windows BMP plus Unicode BMP, dropping the legacy Macintosh
  subtable.
- Version string and `head.fontRevision` now agree.

### Coverage

- Added U+2010 (hyphen), U+200C (ZWNJ), U+200D (ZWJ) and U+061C (Arabic letter
  mark) to both weights, and U+00A0 (no-break space) to Light.

### Known remaining issues

- **K24 has no kerning at all** — neither weight has a `kern` feature in GPOS,
  where Lenos and Aveno both do. Kerning cannot be invented, so this is left as
  found.
- U+066B (٫ decimal separator) and U+066C (٬ thousands separator) are absent.
  Both need drawing.
- Light and Bold still have different glyph sets: Bold carries 28 Latin
  codepoints Light lacks. Reconciling them is design work.
